## Initial analysis

A `.docx` is just a ZIP of XML. Everything the prompt asks for ("what the software wrote
down", "what they deleted before send") lives in the document's metadata and
tracked-changes markup:

```bash
unzip -o NL-COMPLIANCE-0915.docx -d extracted
```

Relevant parts:

- `docProps/core.xml` — authorship metadata
- `docProps/app.xml` — template path / company
- `word/document.xml` — body text **and** revision markup (`<w:ins>` / `<w:del>`)

## The core concept — metadata + tracked changes expose the real author

The visible byline is a costume; the office metadata and a tracked deletion give up both
the real author and the deleted text.

**Who was really at the keyboard** (`docProps/`):

| Field | Value |
|---|---|
| `dc:creator` | `M. Reyes` ← the "costume" byline |
| `lastModifiedBy` | `svc-docgen` (generated by python-docx) |
| `app.xml` Template | `C:\Users\`**`akessler`**`\AppData\Roaming\Microsoft\Templates\NL_internal.dotm` |
| `app.xml` Company | Decima Cloud Services |

The template path leaks the real Windows user: **`akessler`**.

**What they deleted before send** (`word/document.xml`) — a tracked deletion authored by
the same user:

```xml
<w:del w:author="akessler" w:date="2026-09-15T03:41:00Z">
  <w:r><w:delText>-- AK: leaving my name off this one. the Q3 audit numbers don't
  reconcile and Reyes won't sign the real version. number{the_author_is_not_the_byline}
  </w:delText></w:r>
</w:del>
```

## Solving it

```bash
grep -o 'w:author="[^"]*"' extracted/word/document.xml    # akessler authored the deletion
grep -o 'number{[^}]*}'     extracted/word/document.xml    # the deleted flag
grep -i template            extracted/docProps/app.xml     # akessler template path
```

The deleted `w:delText` contains the flag directly.

## Flag

```
number{the_author_is_not_the_byline}
```

## Key takeaways

- **OOXML forensics 101:** a `.docx`/`.xlsx`/`.pptx` is a ZIP — `unzip` it and read the
  XML. `docProps/core.xml` and `app.xml` hold creator, last-editor, company and template
  paths (which often leak a real username).
- **Tracked changes never truly vanish.** `<w:del>`/`w:delText` preserve "deleted" text
  and the author who deleted it — exactly "what they took back before anyone saw it".
